# 0020: Repository layout

Date: 2026-11-24

## Status

Accepted

## Context

The bootstrap brief sketched a layout with one `engine/include/veach/` tree for all public headers. Agents tend to reach across module boundaries unless the build stops them. Generated artifacts (Luau types, JSON Schemas) must be easy to find and diff.

## Decision

```
AGENTS.md  CLAUDE.md (@AGENTS.md)  README.md  LICENSE  THIRD_PARTY_NOTICES.md
CMakeLists.txt  CMakePresets.json  .luaurc  .clang-format  .clang-tidy  .gitattributes
cmake/                 CPM.cmake (vendored), VeachOptions/Compiler/Dependencies/Targets.cmake
engine/
  include/veach/veach.hpp      the umbrella header (only file in engine/include)
  <area>/include/veach/<area>/ public headers of one area
  <area>/src/                  sources and private headers
apps/lab/              veach-lab: src/, scripts/, veach.project.json
tools/veach-cli/       the `veach` binary (types, schemas)
tools/scripts/         repo scripts (check_repo.py)
tests/                 one doctest binary (veach-tests) + CTest integration tests
types/veach.d.luau     generated by `veach types`, committed
schemas/               generated by `veach schemas`, committed
docs/                  VISION, ARCHITECTURE, adr/, specs/, backlog/, guides/, reference/errors.md
.github/workflows/     CI
.claude/               settings, hooks, slash commands
```

- **Each engine area is its own static library**, `veach_<area>` with alias `veach::<area>`, created by `veach_add_engine_library()`.
- The layering is enforced by link dependencies (`engine/CMakeLists.txt`):
  - `core` ← `ecs` ← `platform` ← `asset` ← `script`;
  - `platform` ← `rhi` ← `render` (the RHI uses `platform` only for `NativeWindowHandle`; SDL is private to `veach_platform`);
  - `runtime` depends on all of them;
  - `veach::veach` is an INTERFACE target that adds the umbrella include dir and links `runtime`. Apps and tools link only `veach::veach`.
- **Deviation from the sketch:** per-area include directories instead of one shared `engine/include` tree. An area can include another area's headers only if it links that area, so a layering violation is a compile error.
- **Generated files are committed** so editors and the Luau LSP work without a build, and CTest fails when they are stale.

## Consequences

- Adding an area means a directory, a `CMakeLists.txt` with `veach_add_engine_library`, and an `add_subdirectory` in dependency order.
- Include paths read as `<veach/<area>/<file>.hpp>` everywhere. Private headers stay in `src/`.
- Committed generated files mean contributors must regenerate after changing reflected types. The failing test says exactly which command to run.

## Alternatives considered

- **Single `engine/include/veach/**` tree (the original sketch).** Simpler to browse, but nothing stops `core` from including `script` headers.
- **One engine library.** Fastest to set up, but no enforced boundaries and coarser incremental rebuilds.
- **Generated files only in the build directory.** Editors can't see them without a build, and staleness is invisible in review.
