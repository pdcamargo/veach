# 0024: Repository layout

Date: 2026-11-27

## Status

Accepted. Carried over from the pathtracer-era series (old ADR 0020), with `space/` added.

## Context

Agents tend to reach across module boundaries unless the build stops them. Generated artifacts (Luau types, JSON
Schemas) must be easy to find and diff. The space toolbox needs a home that keeps it above the engine.

## Decision

```
AGENTS.md  CLAUDE.md (@AGENTS.md)  README.md  LICENSE  THIRD_PARTY_NOTICES.md
CMakeLists.txt  CMakePresets.json  .luaurc  .clang-format  .clang-tidy  .gitattributes  .mcp.json
cmake/                 CPM.cmake (vendored), VeachOptions/Compiler/Dependencies/Targets/Shaders.cmake,
                       embed_shaders.cmake, patch_msl.cmake
engine/
  include/veach/veach.hpp      the umbrella header (only file in engine/include)
  <area>/include/veach/<area>/ public headers of one area
  <area>/src/                  sources and private headers
  render/shaders/              engine Slang modules and shaders
space/                 the space toolbox, a layer above the engine (ADR 0042)
apps/lab/              veach-lab: src/, scripts/, shaders/, assets/, types/, veach.project.json
tools/veach-cli/       the `veach` binary (types, schemas, imgdiff)
tools/scripts/         repo scripts (check_repo.py, pre-push.sh, format hook, leak check)
tools/githooks/        the git hooks (core.hooksPath), tools/push.sh the way to push
tools/assets/          asset preparation scripts; tools/metal-repros/ Metal compiler repros; tools/ci/ CI helpers
tests/                 one doctest binary (veach-tests) + CTest integration tests; golden/ (LFS), cmake/, mcp/
types/veach.d.luau     generated by `veach types`, committed
schemas/               generated by `veach schemas`, committed
docs/                  VISION, ARCHITECTURE, adr/, specs/, backlog/, guides/, reference/
.github/workflows/     CI
.claude/               settings, hooks, slash commands
```

- **Each engine area is its own static library**, `veach_<area>` with alias `veach::<area>`, created by
  `veach_add_engine_library()`. Areas, in dependency order (`engine/CMakeLists.txt`): core, ecs, platform, asset,
  script, rhi, render, runtime.
- The layering is enforced by link dependencies:
  - `core` ← `ecs` ← `platform` ← `asset` ← `script`;
  - `platform` ← `rhi` ← `render` (the RHI uses `platform` only for `NativeWindowHandle`; SDL is private to
    `veach_platform`); `render` also links `ecs` and `asset`;
  - `runtime` depends on all of them;
  - `veach::veach` is an INTERFACE target that adds the umbrella include dir and links `runtime`. Apps, tools and
    `space/` link only `veach::veach`.
- **Per-area include directories**, not one shared `engine/include` tree: an area can include another area's
  headers only if it links that area, so a layering violation is a compile error.
- **`space/` sits next to `engine/`, never inside it.** The engine does not know it exists ([ADR 0042](0042-space-toolbox-layering.md)).
- **Generated files are committed** so editors and the Luau LSP work without a build, and CTest fails when they
  are stale.

## Consequences

- Adding an area means a directory, a `CMakeLists.txt` with `veach_add_engine_library`, and an `add_subdirectory`
  in dependency order.
- Include paths read as `<veach/<area>/<file>.hpp>` everywhere. Private headers stay in `src/`.
- Contributors regenerate committed files after changing reflected types; the failing test names the command.

## Alternatives considered

- **A single `engine/include/veach/**` tree.** Simpler to browse, but nothing stops `core` from including
  `script` headers.
- **One engine library.** No enforced boundaries and coarser incremental rebuilds.
- **Generated files only in the build directory.** Editors can't see them without a build, and staleness is
  invisible in review.
- **The toolbox as engine areas (`engine/terrain`, ...).** Lets engine code depend on game-shaped code; see
  ADR 0042.
