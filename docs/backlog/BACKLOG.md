# Veach backlog

## Now

- **VCH-057** Lost accumulation history on Metal — *render* — Path-traced pixels in aligned 4x4 tiles sometimes read back something other than what the previous frame wrote (dark tiles that fade slowly). `render.history_lost` now detects it and fails the run, with the count and frame. **Seen:** 4 windowed/headless runs 12:35-12:38 and ~7 of ~150 runs 12:50-12:57 on 2026-11-25, every time while another process was busy on the machine (an owner's lab session; a Blender conversion and Cycles render of Bistro); also with one frame in flight, so not a cross-frame overlap. **Not reproduced (stress harness, same build):** 11,615 runs under GPU contention (4 concurrent labs + golden loops), ~5,000 under 26 GB of RAM pressure, 360 with 24 of 28 GB of the Metal working set held by another process, 1,875 with `MTL_SHADER_VALIDATION=1` (no validation errors either). **Checked in code:** (a) no heaps or untracked resources: every resource is created tracked and each graph pass is its own encoder, so Metal orders them; (b) every pass declares what it touches and the backend makes it resident with `useResource` (null descriptors included); (c) the render graph pools textures but never aliases memory, and the accumulation is persistent. **Lead (2026-11-25):** with `MTL_SHADER_VALIDATION=1` (every debug build), Metal returns ray-query results that vary run to run for shaders that read instance data after a hit or trace twice, even in release builds and with one frame in flight; without it the same shaders are exact. Check whether the lost history happens only in validated (debug) runs. Next time the detector fires: Xcode GPU capture of that frame, and note what else was running.
## Next

- **VCH-067** Candela: a steady cache — *render* — Read alone at the visible surface (`Candela.gather = "surface_cache"`), the radiance cache flickers 0.0107 / 0.0074 / 0.0138 FLIP between frames (Cornell, Sponza, Bistro; limit 0.005), so screen probes would inherit it. Its 3-frame average moves each cell a third of the way to a noisy mean per update (20% change per frame); a 32-frame average cuts that to 4% and flicker to 0.008 but loses the light-off response. The owner decides the fix (review packet, 2026-11-26). [spec](../specs/candela/spec.md)
- **VCH-066** Candela: unbiased spatial reuse — *render* — Off by default. Plain 1/M weights darkened (-5% on the Cornell box); pairwise MIS in area measure exploded (+400% on Sponza, from weights computed with different normals than later passes used); with the reconnection Jacobian it leaves fireflies (516 pixels above 0.5 on the Cornell box). Fix the fireflies (clamping the Jacobian, or confidence caps on neighbors), then measure whether reuse lowers flicker. [spec](../specs/candela/spec.md)
- **VCH-062** Denoiser: fine foliage detail — *render* — Bistro's denoised image is 0.0151 FLIP from the direct-light reference where its undenoised lighting converges to 0.0148: the a-trous filter softens sunlit leaf edges. Candidates: leaf-aware edge stopping (alpha-tested surfaces' own normal/ID weight), fewer iterations where history is long. Baseline and tolerance: ADR 0047.
- **VCH-060** Blended materials in the real-time renderer — *render* — The visibility buffer draws `BLEND` materials masked at 0.5; the path tracer covers them stochastically. Sponza's dirt decal shows the difference: +6% mean luminance against the reference. Stochastic or weighted coverage in the visibility pass, resolved by the denoiser and the upscaler.
- **VCH-005** `Behavior` component — *script* — `veach.behavior(Component, { on_update = function(self, dt) ... end })` sugar for per-entity scripts, run internally as an ordinary Simulation system with batched dispatch. No separate update path.
- **VCH-009** Runtime shader compilation — *render* — Build-time Slang → metallib/DXIL exists ([ADR 0026](../adr/0026-shader-compilation.md)). Add libslang at run time for shader hot reload, and a pipeline cache.

## Later

- **VCH-068** AMD FSR where MetalFX is not available — *render* — Windows upscales with our TAAU, visibly softer than MetalFX at 0.5 (Bistro noon: 0.056 FLIP from native against MetalFX's 0.046; thin wires break up). Replace it there with FSR rather than tuning TAAU. Licenses, checked 2026-11-26: FSR 3.1 (FidelityFX SDK v1.1.4) is MIT with full source; the SDK 2.x line (FSR 4) ships its runtime as binaries under AMD's own license (binary redistribution only, no reverse engineering). The owner decides which before anything is added (ADR 0049).
- **VCH-065** Dynamic resolution scaling — *render* — The render scale adapts each frame to hold the quality tier's frame time (a floor near 0.33, the tier's scale as the ceiling), with the temporal upscaler absorbing the change: how tiers work on hardware we cannot measure. The base M3/M4 estimate in [ADR 0049](../adr/0049-frame-budget-and-quality-tiers.md) is about 31 ms for Performance at 0.5 scale, so they need it to hold 60 fps. Needs the upscalers to take a changing input size without a history reset.

## Done

- **VCH-064** False sky specks in the path tracer's foliage — *render* — Reported as string-light bulbs missing from the real-time image under the sky. The real-time image was right: the path tracer's `trace()` gave up on a ray after 16 transparent leaf texels and reported a miss, so camera rays through dense cypresses saw the sky (black, so invisible, without one). Now 64 layers, and a ray that runs out stops at the last leaf it reached. Bistro against the reference: noon 0.0312 -> 0.0150 FLIP, -2.37% -> -0.67% luminance; sunset 0.0406 -> 0.0217, -8.28% -> -0.99%; the luminance exceptions are gone.
