# Veach backlog

Conventions: [README.md](README.md). Add items with `/backlog`.

## Now

- **VCH-070** Research phase — *process* — Answer the eight open questions in [ARCHITECTURE.md](../ARCHITECTURE.md#open-questions-research-phase): large-world coordinates (floating origin, double, int64) through ECS, physics, extraction and rendering; the representation and LOD of editable volumetric terrain (density/SDF, meshing, seams, chunk streaming, caves); the seed hierarchy and procgen determinism (galaxy → system → planet → biome → chunk → object) with player edits stored on top; the procgen graph model (C++ and GPU compute vs Luau, how users extend it); the networking model (authority, edits as deltas, synced vs regenerated, fixed-step determinism); simulation LOD for fauna, flora, NPCs and factions; the real-time PBR renderer on the render graph (forward+/clustered vs visibility buffer) and planet-scale render features (atmosphere, terrain, vegetation, ocean, clouds) as `RenderFeature`s; physics at planetary scale (Box3D vs Jolt with double precision). Output: one ADR per answer, plus the spikes' measured results. No toolbox features before the answers. [ADR 0001](../adr/0001-reset.md)

## Next

- **VCH-071** RHI: indirect dispatch and indirect draw — *rhi* — Research-phase input. GPU-driven work (terrain meshing, culling, vegetation scattering) needs dispatch and draw arguments written by the GPU: Metal and DX12 (`ExecuteIndirect`), a no-op on null. [audit](../reference/rhi-capabilities.md)
- **VCH-072** RHI: 3D textures and texture arrays — *rhi* — Research-phase input. Density fields, clouds and volumes need 3D textures; the sky's aerial-perspective volume is a 2D atlas today because they are missing. Texture arrays for terrain material layers. [audit](../reference/rhi-capabilities.md)
- **VCH-073** RHI: non-blocking readback — *rhi* — Research-phase input. A way to ask whether a submission has completed without waiting, so GPU-built data (terrain meshes) reaches CPU systems (physics) without stalling a frame. Today `Device::wait()` blocks, and readbacks rely on the frame slot coming round. [audit](../reference/rhi-capabilities.md)
- **VCH-074** RHI: async compute queue — *rhi* — Research-phase input. A second queue for compute (procgen, meshing) beside graphics, with cross-queue synchronization derived by the render graph. Today there is one graphics queue ([ADR 0030](../adr/0030-frame-and-sync-model.md)). [audit](../reference/rhi-capabilities.md)
- **VCH-075** RHI: atomics beyond 32-bit buffer atomics — *rhi* — Research-phase input. Texture atomics and 64-bit atomics (meshing, voxel edits, GPU hash maps), verified on Metal and DX12/WARP. 32-bit buffer atomics work on both today. [audit](../reference/rhi-capabilities.md)
- **VCH-076** RHI: updating textures after creation — *rhi* — Research-phase input. Buffer-to-texture copies and partial uploads for streamed data (terrain chunks, virtual textures). Today texture data is uploaded only at creation. [audit](../reference/rhi-capabilities.md)
- **VCH-057** Lost accumulation history on Metal — *render* — Photo mode's path-traced pixels, in aligned 4x4 tiles, sometimes read back something other than what the previous frame wrote (dark tiles that fade). `render.history_lost` detects it and fails the run. Seen only while another process was busy on the GPU; not reproduced by a stress harness (GPU contention, memory pressure, shader validation). Lead: with `MTL_SHADER_VALIDATION=1` Metal's ray-query results vary run to run; check whether the loss happens only in validated runs. Next time it fires: an Xcode GPU capture of that frame. [spec](../specs/photo-mode/spec.md)
- **VCH-005** `Behavior` component — *script* — `veach.behavior(Component, { on_update = function(self, dt) ... end })` sugar for per-entity scripts, run as an ordinary Simulation system with batched dispatch. No separate update path.
- **VCH-009** Runtime shader compilation — *render* — Build-time Slang → metallib/DXIL exists ([ADR 0009](../adr/0009-shader-compilation.md)). Add libslang at run time for shader hot reload, and a pipeline cache.

- **VCH-050** DX12 on real hardware — *rhi* — Run the DX12 goldens and a long frames-in-flight soak on a physical DX12 GPU (vendor drivers, real timings; DXR 1.1 for photo mode), and present to a real display: on the hosted runner about one `Present` in 60 fails with `E_INVALIDARG`, with or without a resize, and no debug layer explains it; the windowed test tolerates exactly that, only under `VEACH_CI_HOSTED_WINDOWS=1`. Blocked: no Windows GPU machine or runner ([ADR 0032](../adr/0032-windows-verified-in-hosted-ci.md)). Unblocked by a paid GPU runner or a Windows machine registered as a runner.
